# v0.1.0 future release commands

Status: documentation only; do not run during Phase 4.2

Every command that changes public state is marked **PUBLIC/DESTRUCTIVE**. Stop on the first unexpected result.
Never force-push, reuse a published version, replace an existing tag, or print a credential.

## Safety ordering note

The requested stage list places repository visibility at stage 13. npm provenance requires a public source
repository, so an approved provenance-bearing release must execute stage 13 immediately after stage 9, then
return to stages 10–12. If public visibility is not approved, stop before npm publication; do not silently
publish without provenance.

## 1. Final synchronization

```sh
git status --short --branch
git fetch origin
git rev-parse HEAD
git rev-parse origin/main
git tag --list v0.1.0
gh release view v0.1.0 --repo SUDARSHANCHAUDHARI/TemporalThread
```

Require a clean `main`, identical local/remote commits, and no existing `v0.1.0` tag or release.

## 7. Release commit

**PUBLIC-HISTORY MUTATION — requires release approval.**

```sh
git add CHANGELOG.md docs/RELEASE-NOTES-v0.1.0-DRAFT.md
git commit -m "chore: finalize TemporalThread v0.1.0 release"
git status --short --branch
```

Rerun stages 2 and 3 for this exact commit if the release commit changes packaged or executable content.

## 8. Signed or annotated tag

**PUBLIC/DESTRUCTIVE — requires tag approval.** Prefer a signed tag when the maintainer's verified signing
setup is available:

```sh
git tag -s v0.1.0 -m "TemporalThread v0.1.0"
git tag -v v0.1.0
```

If signing is unavailable and that exception is explicitly accepted:

```sh
git tag -a v0.1.0 -m "TemporalThread v0.1.0"
git show --no-patch v0.1.0
```

## 9. Push

**PUBLIC/DESTRUCTIVE — requires push/tag approval.**

```sh

git ls-remote --tags origin v0.1.0
```

Never use `--force`.

## 10. npm publication in dependency order

**PUBLIC/IRREVERSIBLE — requires npm scope, 2FA/provenance, and publication approval.** Recheck ownership and
availability first:

Run the exact publish list from `docs/NPM-DISTRIBUTION-PLAN.md` in a protected GitHub-hosted job, one

## 15. Rollback or deprecation

**PUBLIC/DESTRUCTIVE — incident approval required.** Stop further dependent publishes first. Prefer a
fix-forward release and deprecation warning:

```sh
npm deprecate temporalthread@0.1.0 "Known issue; use <fixed-version>"
npm deprecate @temporalthread/<affected-package>@0.1.0 "Known issue; use <fixed-version>"
```

Do not delete/repoint the Git tag. Do not unpublish by default. If accidental secret or unsafe content was
published, follow the incident plan and current npm unpublish policy, revoke credentials, rotate affected
secrets, and publish a new immutable version.
