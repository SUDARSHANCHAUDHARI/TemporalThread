# v0.1.0 release status

Assessment date: 2026-07-26

## Current decision

**MVP implementation: complete**

**Public v0.1.0 release: blocked**

TemporalThread has its intended MVP code and documentation. No additional feature phase is required before release preparation.

## Repository state

- Repository visibility: private.
- GitHub Actions workflows: none.
- Normal development must use a branch and pull request.
- Direct changes to `main`, CI, release automation, tags, releases, and publication require explicit owner approval.

## Local validation before release

Run these commands locally once against the exact release commit:

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm audit --prod --audit-level high
```

The larger MCP, SQLite recovery, package, and release-verification scripts are manual tools. They are not required for routine commits and should be run only when relevant to a release or a specific change.

No current GitHub Actions result exists because all workflows were removed. This document does not claim that the latest commit has passed local validation.

## Remaining release blockers

### 1. MCP SDK dependency security

The current stable `@modelcontextprotocol/sdk` dependency still leads clean packed consumers to the blocked Hono dependency line documented by the project. Do not publish the npm packages until a secure stable dependency path is available and verified locally.

### 2. npm ownership and account security

Before publication, the owner must personally confirm:

- authority over the intended `@temporalthread` npm scope;
- package publishing permission;
- write-protection 2FA;
- secure recovery-code storage; and
- explicit approval for publication.

Do not request, store, or commit npm tokens or recovery codes.

### 3. Owner release decision

The following remain owner-only decisions:

- making the repository public;
- publishing npm packages;
- creating a Git tag or GitHub release; and
- announcing the project publicly.

## Codex compatibility status

The Codex package, installer, schemas, hooks, and MCP behavior have automated test coverage in the repository. Real Codex CLI/desktop trust, UI, skill discovery, and model behavior were skipped by the owner and remain **not tested**.

Documentation must not claim certified real-host Codex compatibility.

## Not required for the MVP

The following are post-MVP work and must not delay the current release:

- JSON import;
- broader natural-language parsing;
- additional host integrations;
- hosted services;
- telemetry;
- dashboards; and
- new CI or release automation.

## Exact next step

Wait for the secure stable MCP SDK dependency path. Then run the five local validation commands, verify the packed dependency graph locally, and ask the owner for explicit publication approval.
